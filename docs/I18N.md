# Internationalisation

## Langues supportées

Le programme prend en charge cinq langues :

| Code | Langue |
| ------ | -------- |
| `fr` | Français |
| `en` | Anglais (par défaut) |
| `es` | Espagnol |
| `de` | Allemand |
| `it` | Italien |

## Sélection de la langue

L'ordre de résolution est :

1. l'option CLI `--lang xx` ;
2. la variable d'environnement `MOON_LANG` ;
3. la variable d'environnement `LANG` ;
4. l'anglais par défaut.

`cli_parse` se contente de résoudre la langue et de l'exposer dans
`CliArgs.lang` : il ne modifie pas l'état global. `main` applique ensuite la
langue avec `i18n_set_lang` avant d'afficher un message d'erreur ou l'usage,
y compris lorsque l'analyse des arguments échoue.

Exemples :

```bash
MOON_LANG=fr moon_duration 2026-11-14
LANG=de_DE.UTF-8 moon_duration 2026-11-14
moon_duration --lang it 2026-11-14
```

Les valeurs de `LANG` de la forme `fr_FR.UTF-8` sont acceptées : seul le code de
langue avant `_`, `.` ou `@` est utilisé.

## Chaînes localisées

Le module `i18n` expose :

- les noms des jours de la semaine ;
- les noms des huit phases lunaires ;
- les libellés du rapport (date, lieu, aperçu, lever, coucher, durée, phase,
  illumination, inclinaison) ;
- les messages d'erreur CLI ;
- l'avertissement de plage de validité du modèle (1900..3000) ;
- les chaînes d'usage, via `i18n_usage_strings()` qui les renvoient par valeur
  dans une structure `I18nUsageStrings` (aucun état partagé entre appels).

Les traductions sont regroupées dans des tableaux statiques dans `src/i18n.c`.
Le module `i18n` fournit les chaînes ; le formatage de l'usage reste dans
`src/cli.c` (`cli_print_usage()`).

## Ajouter une chaîne

1. Ajouter le champ dans la structure `LangStrings`.
2. Ajouter la traduction dans chaque tableau de `lang_tables`.
3. Ajouter une fonction d'accès dans `include/i18n.h` et `src/i18n.c`.
4. Ajouter un test dans `tests/test_i18n.c`.
5. Mettre à jour la documentation si nécessaire.

Toute chaîne utilisateur doit être présente dans les cinq langues et couverte
par un test.
